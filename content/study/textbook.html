      1.1Ключевые понятия

      record
      Неизменяемый класс-носитель данных: конструктор, equals, hashCode и toString генерируются сами.
      sealed
      Класс или интерфейс с закрытым списком наследников. Вместе с pattern matching даёт исчерпывающий switch.
      Stream API
      Декларативная обработка коллекций: filter, map, collect, groupingBy.
      Optional
      Явное «значение может отсутствовать». Задуман как тип возврата.
      Virtual threads
      Лёгкие потоки Java 21: тысячи одновременных блокирующих операций ввода-вывода без пулов.
      Gradle / Maven
      Сборка, зависимости, запуск тестов.

      1.4Задачи с решениями

      Задача 1.1. Топ-3 слов

      Напишите метод top3(String text), который возвращает три самых частых слова текста без учёта регистра. Только Stream API, без циклов.

      Показать решение

      Регулярное выражение [^\p{L}\p{N}]+ режет по всему, что не буква и не цифра, поэтому работает и для кириллицы (обычный \W считает кириллицу «не словом»). groupingBy + counting строят частоты, затем сортировка по значению по убыванию.

      Задача 1.2. Площадь фигур

      Опишите фигуры круг и прямоугольник через sealed-интерфейс и records. Напишите area(Shape s) через switch с pattern matching без ветки default.

      Показать решение

      Компилятор знает все разрешённые реализации sealed-интерфейса, поэтому switch исчерпывающий и default не нужен. Если добавить новую фигуру, код перестанет компилироваться, пока её не обработают, — это и есть польза sealed.

      Упражнения

      Проверь себя

      Чем record отличается от обычного класса?

      Поля final, а конструктор, equals, hashCode, toString и методы доступа генерируются автоматически. Record не может наследовать другой класс, но может реализовывать интерфейсы.

      Когда виртуальные потоки дают выигрыш, а когда нет?

      Выигрыш — при большом числе блокирующих операций ввода-вывода (HTTP, база, файлы). Для вычислительных задач они не быстрее обычных: число ядер не меняется.

      Почему Optional не стоит делать полем класса или параметром метода?

      Он задуман как тип возврата: «результата может не быть». В полях он усложняет сериализацию и добавляет лишний объект, в параметрах лучше перегрузка или null-проверка.

      Чем map отличается от flatMap в Stream?

      map превращает каждый элемент в один новый, flatMap — в поток элементов и «расплющивает» их в один общий поток.

      2.1Ключевые понятия

      Нормализация
      Разбиение данных по таблицам так, чтобы факт хранился в одном месте.
      Индекс
      Структура (обычно B-tree), ускоряющая поиск. Составной индекс (a, b) работает для запросов по a и по (a, b).
      ACID
      Атомарность, согласованность, изоляция, долговечность транзакции.
      Миграция
      Версионированное изменение схемы (Flyway: V1__init.sql, V2__…).
      N+1
      Один запрос за списком и ещё N — за связанными сущностями каждого элемента.

      2.4Задачи с решениями

      Задача 2.1. Прогресс проектов

      Для каждого проекта выведите общее число задач, число задач DONE и процент выполненных. Проекты без задач тоже должны попасть в отчёт. Отсортируйте по проценту.

      Показать решение

      LEFT JOIN оставляет проекты без задач. COUNT(t.id) не считает NULL, поэтому у пустого проекта total = 0. NULLIF защищает от деления на ноль, FILTER — компактная замена SUM(CASE …).

      Задача 2.2. Убрать N+1

      Метод projectRepository.findAll(), а затем project.getTasks() в цикле даёт 1 + N запросов. Исправьте одним запросом.

      Показать решение

      join fetch загружает проекты и их задачи одним SQL-запросом. distinct убирает дубликаты проектов в результате. Для пагинации fetch join по коллекции не подходит — там используют batch fetching (@BatchSize).

      Упражнения

      Проверь себя

      Что такое N+1 и как его найти?

      Один запрос за списком плюс отдельный запрос за связанными данными каждого элемента. Видно в логе SQL (spring.jpa.show-sql или datasource-proxy). Лечится JOIN FETCH, @EntityGraph или batch fetching.

      Поможет ли индекс (project_id, status) запросу только по status?

      Обычно нет: B-tree индекс используется по левому префиксу. Для поиска только по status нужен свой индекс.

      От чего защищает уровень изоляции READ COMMITTED и от чего нет?

      Защищает от «грязного чтения» незафиксированных данных. Не защищает от неповторяющегося чтения и фантомов: повторный SELECT в той же транзакции может вернуть другой результат.

      3.4Задачи с решениями

      Задача 3.1. Единый формат ошибок

      Сделайте обработчик, который на ошибку валидации отдаёт 400 со списком полей, а на «задача не найдена» — 404. Оба ответа — в формате ProblemDetail.

      Показать решение

      @RestControllerAdvice применяется ко всем контроллерам. Spring сам выставит Content-Type: application/problem+json. Третий аргумент toMap нужен, если у поля две ошибки — иначе будет исключение о дубликате ключа.

      Задача 3.2. Тест контроллера

      Напишите тест: POST с пустым title должен вернуть 400 и поле errors.title в ответе.

      Показать решение

      @WebMvcTest поднимает только веб-слой и ваш @RestControllerAdvice. Сервис заменён моком: тест проверяет именно валидацию и формат ошибки, а не бизнес-логику. В CreateTask на поле title должна стоять аннотация @NotBlank.

      Упражнения

      Проверь себя

      Почему внедрение через конструктор лучше, чем @Autowired на поле?

      Зависимости видны в сигнатуре, поля можно сделать final, класс легко создать в unit-тесте без Spring, а циклические зависимости обнаруживаются сразу.

      Какой статус вернуть при создании ресурса и при ошибке валидации?

      201 Created с заголовком Location. При ошибке валидации — 400 Bad Request (иногда 422) с телом ProblemDetail, где перечислены поля.

      Чем @WebMvcTest отличается от @SpringBootTest?

      @WebMvcTest поднимает только веб-слой (контроллеры, MockMvc), сервисы подменяются моками; тест быстрый. @SpringBootTest поднимает весь контекст приложения.

      Чем PUT отличается от PATCH?

      PUT заменяет ресурс целиком и идемпотентен. PATCH меняет часть полей.

      4.1Ключевые понятия

      Standalone-компонент
      Компонент без NgModule: сам перечисляет, что импортирует. Стандарт с Angular 17.
      Signal
      Реактивное значение: signal(), производное — computed(), побочный эффект — effect().
      Control flow
      Встроенные @if, @for, @switch в шаблоне вместо *ngIf и *ngFor.
      Observable
      Поток событий RxJS. HttpClient возвращает Observable.
      switchMap
      Оператор, который отменяет предыдущий запрос, когда приходит новое значение. Основа «живого» поиска.
      Interceptor
      Функция, через которую проходит каждый HTTP-запрос: токен, ошибки, индикатор загрузки.
      Guard
      Проверка перед переходом по маршруту (например, «пользователь вошёл?»).

      4.4Задачи с решениями

      Задача 4.1. Живой поиск

      Сделайте поле поиска задач: запрос уходит через 300 мс после остановки ввода, при новом вводе старый запрос отменяется, при ошибке список пустой, меньше двух символов — не искать.

      Показать решение

      debounceTime ждёт паузу в вводе, distinctUntilChanged не повторяет тот же запрос, switchMap отменяет предыдущий HTTP-запрос. catchError стоит внутри switchMap: иначе одна ошибка навсегда завершит весь поток. toSignal сам отписывается при уничтожении компонента.

      Задача 4.2. Interceptor ошибок

      Напишите функциональный interceptor: при ответе 5xx показать тост «Сервер недоступен», ошибку пробросить дальше.

      Показать решение

      Функциональные interceptors — современный способ вместо классов с HttpInterceptor. inject() работает внутри них, потому что Angular вызывает их в контексте внедрения. throwError возвращает ошибку вызывающему коду, чтобы компонент тоже мог отреагировать.

      Проверь себя

      Когда брать signal, а когда Observable?

      Signal — для состояния, которое нужно прочитать «сейчас» и показать в шаблоне. Observable — для потоков событий во времени: HTTP, ввод с debounce, WebSocket. Между ними переходят через toSignal и toObservable.

      Почему для поиска switchMap, а не mergeMap?

      switchMap отменяет предыдущий запрос, когда пользователь ввёл новый символ, поэтому старый ответ не перезапишет новый. mergeMap выполняет все запросы параллельно, и ответы могут прийти не по порядку.

      Зачем в @for нужен track?

      По нему Angular узнаёт элементы при обновлении списка и перерисовывает только изменённые, а не весь список.

      Где во фронтенде хранить токен доступа?

      Безопаснее всего в памяти, а обновлять через refresh-механизм библиотеки OIDC. localStorage доступен любому скрипту при XSS. В крупных системах часто используют паттерн BFF: токены на сервере, браузер держит только HttpOnly-cookie.

      5.4Задачи с решениями

      Задача 5.1. Роли из Keycloak

      Keycloak кладёт роли в JWT в поле realm_access.roles, а Spring ждёт ROLE_…. Напишите конвертер, чтобы работал hasRole("ADMIN").

      Показать решение

      Бин JwtAuthenticationConverter Spring Security подхватывает сам при oauth2ResourceServer(o -> o.jwt(...)). Префикс ROLE_ нужен, потому что hasRole("ADMIN") ищет полномочие ROLE_ADMIN.

      Задача 5.2. Найди уязвимость

      Что не так с этим кодом и как исправить?
      jdbc.query("SELECT * FROM task WHERE title LIKE '%" + q + "%'", mapper);

      Показать решение

      Это SQL-инъекция: пользовательский ввод становится частью SQL-кода. Параметр ? передаётся базе отдельно от текста запроса, поэтому никогда не исполняется как код. Это пункт A03 Injection в OWASP Top 10.

      Упражнения

      Проверь себя

      Чем OAuth 2.0 отличается от OpenID Connect?

      OAuth 2.0 — про доступ к ресурсам (access token). OIDC добавляет вход пользователя: ID token с данными о том, кто вошёл.

      Почему Implicit flow больше не рекомендуют?

      Токен приходит в URL и может утечь через историю, логи или Referer. Для SPA рекомендован Authorization Code + PKCE (OAuth 2.0 Security Best Current Practice).

      Когда 401, а когда 403?

      401 — запрос без действительной аутентификации. 403 — пользователь известен, но прав на действие нет.

      Как защититься от SQL-инъекций?

      Только параметризованные запросы (PreparedStatement, JPA-параметры) и никакой склейки строк с пользовательским вводом. Плюс минимальные права у пользователя БД.

      Задача 6.1. Deployment с пробами

      Опишите Deployment для taskhub-api: 2 реплики, запрос и лимит памяти, readiness- и liveness-пробы на эндпоинты Spring Boot Actuator.

      Упражнения

      Проверь себя

      Чем liveness probe отличается от readiness probe?

      Провал liveness — Kubernetes перезапускает контейнер. Провал readiness — под временно убирается из Service и не получает трафик, но не перезапускается.

      Зачем нужен multi-stage build?

      JDK, Gradle и исходники остаются в промежуточном образе, в итоговом только JRE и jar. Образ меньше, быстрее скачивается и содержит меньше уязвимостей.

      Чем Deployment отличается от StatefulSet?

      Deployment — для одинаковых взаимозаменяемых подов без состояния. StatefulSet даёт подам постоянные имена и собственные тома — для баз данных и брокеров.

      Как не переплатить за учебный аккаунт AWS?

      Включить AWS Budgets с оповещением на почту, создавать ресурсы только через Terraform и после демонстрации выполнять terraform destroy. EKS и NAT Gateway платные даже при простое.

      7.4Задачи с решениями

      Задача 7.1. Идемпотентный консьюмер

      Kafka может доставить событие использования API дважды. Напишите обработчик, который увеличивает счётчик вызовов за день ровно один раз на событие.

      Показать решение

      Таблица processed_event с первичным ключом по id события запоминает обработанные события. Обе вставки в одной транзакции: либо засчитано и запомнено, либо ни то ни другое. Повторная доставка увидит inserted == 0 и ничего не изменит.

      Задача 7.2. Outbox

      При одобрении подписки нужно сохранить её в БД и отправить событие в Kafka. Сделайте так, чтобы событие не потерялось и не ушло без сохранённых данных.

      Показать решение

      Событие пишется в таблицу outbox в той же транзакции, что и данные, — двойной записи больше нет. Отдельная задача публикует неотправленные события. Если она упадёт после отправки, но до markSent, событие уйдёт ещё раз — поэтому консьюмеры и должны быть идемпотентными (задача 7.1).

      Упражнения

      Проверь себя

      Когда микросервисы НЕ нужны?

      Маленькая команда, неясная предметная область, нет автоматизации развёртывания и наблюдаемости. Тогда лучше модульный монолит (Fowler, «MonolithFirst»).

      Какую проблему решает Outbox?

      Проблему «двойной записи»: нельзя атомарно сохранить данные в БД и отправить сообщение в брокер. Outbox делает запись события частью той же транзакции БД.

      Какие состояния у Circuit Breaker?

      CLOSED — вызовы идут; OPEN — вызовы сразу отклоняются; HALF_OPEN — пробные вызовы, чтобы понять, восстановился ли сервис.

      Почему консьюмер Kafka должен быть идемпотентным?

      Обычная гарантия доставки — at-least-once: одно сообщение может прийти дважды (например, после ребалансировки). Повторная обработка не должна портить данные.

      8–10 недельПлатформа API-продуктов

      Небольшая версия того, чем занимается команда API ART в Swisscom: внутренние команды публикуют свои API, потребители подписываются, получают доступ и видят статистику использования. На собеседовании этот проект легко связать с их работой: API Products, IAM, EAI.

      10.1Возможности

      1. Каталог API: загрузка OpenAPI-спецификации, версии, статусы draft / published / deprecated, документация в Swagger UI.
      2. Подписки: потребитель запрашивает доступ, владелец одобряет, выдаются client credentials в Keycloak.
      3. Шлюз: Spring Cloud Gateway проверяет токен, применяет rate limit (Redis) и проксирует запрос.
      4. Учёт использования: шлюз пишет события в Kafka, usage-service считает статистику, портал рисует графики.
      5. Портал на Angular: роли Provider, Consumer, Admin; дашборды, поиск по каталогу.
      6. Уведомления: письмо или webhook, когда API помечен deprecated.

      10.2Архитектура

      Angular portal ──► api-gateway (Spring Cloud Gateway: JWT, rate limit)
                      ├─► catalog-service       (PostgreSQL) ── REST
                      ├─► subscription-service  (PostgreSQL) ── REST + Keycloak Admin API
                      ├─► usage-service         (PostgreSQL / TimescaleDB)
                      └─► demo-backends         (2–3 мок-API)
api-gateway ──события──► Kafka ──► usage-service
                              └──► notification-service
Keycloak (IAM) · Prometheus + Grafana · OpenTelemetry → Jaeger или Tempo
