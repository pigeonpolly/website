      Правила, которые склеивают шаги

      1. Один репозиторий, Gradle-модули. Java-части подключают друг друга через implementation(project(":core")), а не копированием кода.
      2. Чистое ядро. Бизнес-логика живёт в core без фреймворков, поэтому её переиспользуют API и сервис импорта.
      3. Контракт между частями. Frontend и backend связаны файлом api/openapi.json и сгенерированным клиентом; сервисы — описанными событиями Kafka.

      Задача 1.1. Топ-3 слов

      Напишите метод top3(String text), который возвращает три самых частых слова текста без учёта регистра. Только Stream API, без циклов.

      Показать решение

      Регулярное выражение [^\p{L}\p{N}]+ режет по всему, что не буква и не цифра, поэтому работает и для кириллицы (обычный \W считает кириллицу «не словом»). groupingBy + counting строят частоты, затем сортировка по значению по убыванию.

      Задача 1.2. Площадь фигур

      Опишите фигуры круг и прямоугольник через sealed-интерфейс и records. Напишите area(Shape s) через switch с pattern matching без ветки default.

      Показать решение

      Компилятор знает все разрешённые реализации sealed-интерфейса, поэтому switch исчерпывающий и default не нужен. Если добавить новую фигуру, код перестанет компилироваться, пока её не обработают, — это и есть польза sealed.

      Упражнения

      Проверь себя

      Чем record отличается от обычного класса?

      Поля final, а конструктор, equals, hashCode, toString и методы доступа генерируются автоматически. Record не может наследовать другой класс, но может реализовывать интерфейсы.

      Когда виртуальные потоки дают выигрыш, а когда нет?

      Выигрыш — при большом числе блокирующих операций ввода-вывода (HTTP, база, файлы). Для вычислительных задач они не быстрее обычных: число ядер не меняется.

      Почему Optional не стоит делать полем класса или параметром метода?

      Он задуман как тип возврата: «результата может не быть». В полях он усложняет сериализацию и добавляет лишний объект, в параметрах лучше перегрузка или null-проверка.

      Чем map отличается от flatMap в Stream?

      map превращает каждый элемент в один новый, flatMap — в поток элементов и «расплющивает» их в один общий поток.

      Упражнения

      Проверь себя

      Что такое N+1 и как его найти?

      Один запрос за списком плюс отдельный запрос за связанными данными каждого элемента. Видно в логе SQL (spring.jpa.show-sql или datasource-proxy). Лечится JOIN FETCH, @EntityGraph или batch fetching.

      Поможет ли индекс (project_id, status) запросу только по status?

      Обычно нет: B-tree индекс используется по левому префиксу. Для поиска только по status нужен свой индекс.

      От чего защищает уровень изоляции READ COMMITTED и от чего нет?

      Защищает от «грязного чтения» незафиксированных данных. Не защищает от неповторяющегося чтения и фантомов: повторный SELECT в той же транзакции может вернуть другой результат.

      Задача 4.2. Interceptor ошибок

      Напишите функциональный interceptor: при ответе 5xx показать тост «Сервер недоступен», ошибку пробросить дальше.

      Показать решение

      Функциональные interceptors — современный способ вместо классов с HttpInterceptor. inject() работает внутри них, потому что Angular вызывает их в контексте внедрения. throwError возвращает ошибку вызывающему коду, чтобы компонент тоже мог отреагировать.

      Упражнения

      Проверь себя

      Когда брать signal, а когда Observable?

      Signal — для состояния, которое нужно прочитать «сейчас» и показать в шаблоне. Observable — для потоков событий во времени: HTTP, ввод с debounce, WebSocket. Между ними переходят через toSignal и toObservable.

      Почему для поиска switchMap, а не mergeMap?

      switchMap отменяет предыдущий запрос, когда пользователь ввёл новый символ, поэтому старый ответ не перезапишет новый. mergeMap выполняет все запросы параллельно, и ответы могут прийти не по порядку.

      Зачем в @for нужен track?

      По нему Angular узнаёт элементы при обновлении списка и перерисовывает только изменённые, а не весь список.

      Где во фронтенде хранить токен доступа?

      Безопаснее всего в памяти, а обновлять через refresh-механизм библиотеки OIDC. localStorage доступен любому скрипту при XSS. В крупных системах часто используют паттерн BFF: токены на сервере, браузер держит только HttpOnly-cookie.

      Проверь себя

      Чем OAuth 2.0 отличается от OpenID Connect?

      Как защититься от SQL-инъекций?

      Проверь себя

      Чем liveness probe отличается от readiness probe?

      Провал liveness — Kubernetes перезапускает контейнер. Провал readiness — под временно убирается из Service и не получает трафик, но не перезапускается.

      Зачем нужен multi-stage build?

      JDK, Gradle и исходники остаются в промежуточном образе, в итоговом только JRE и jar. Образ меньше, быстрее скачивается и содержит меньше уязвимостей.

      Чем Deployment отличается от StatefulSet?

      Deployment — для одинаковых взаимозаменяемых подов без состояния. StatefulSet даёт подам постоянные имена и собственные тома — для баз данных и брокеров.

      Как не переплатить за учебный аккаунт AWS?

      Включить AWS Budgets с оповещением на почту, создавать ресурсы только через Terraform и после демонстрации выполнять terraform destroy. EKS и NAT Gateway платные даже при простое.

      Задача 7.1. Идемпотентный консьюмер

      Kafka может доставить событие использования API дважды. Напишите обработчик, который увеличивает счётчик вызовов за день ровно один раз на событие.

      Показать решение

      Таблица processed_event с первичным ключом по id события запоминает обработанные события. Обе вставки в одной транзакции: либо засчитано и запомнено, либо ни то ни другое. Повторная доставка увидит inserted == 0 и ничего не изменит.

      Задача 7.2. Outbox

      При одобрении подписки нужно сохранить её в БД и отправить событие в Kafka. Сделайте так, чтобы событие не потерялось и не ушло без сохранённых данных.

      Показать решение

      Событие пишется в таблицу outbox в той же транзакции, что и данные, — двойной записи больше нет. Отдельная задача публикует неотправленные события. Если она упадёт после отправки, но до markSent, событие уйдёт ещё раз — поэтому консьюмеры и должны быть идемпотентными (задача 7.1).

      Упражнения

      Проверь себя

      Когда микросервисы НЕ нужны?

      Маленькая команда, неясная предметная область, нет автоматизации развёртывания и наблюдаемости. Тогда лучше модульный монолит (Fowler, «MonolithFirst»).

      Какую проблему решает Outbox?

      Проблему «двойной записи»: нельзя атомарно сохранить данные в БД и отправить сообщение в брокер. Outbox делает запись события частью той же транзакции БД.

      Какие состояния у Circuit Breaker?

      CLOSED — вызовы идут; OPEN — вызовы сразу отклоняются; HALF_OPEN — пробные вызовы, чтобы понять, восстановился ли сервис.

      Почему консьюмер Kafka должен быть идемпотентным?

      Обычная гарантия доставки — at-least-once: одно сообщение может прийти дважды (например, после ребалансировки). Повторная обработка не должна портить данные.

      Минимальная версия продукта, которая уже решает главную проблему и позволяет проверить, нужен ли он людям.

      Ограничение PostgreSQL: строки не могут «пересекаться» по заданному правилу, например по времени записи к одному мастеру.

      Веб-приложение, которое устанавливается на телефон и работает с кэшем без сети благодаря service worker.
      Staging
      Копия продакшена для проверки перед выпуском.

      11.11Задачи с решениями

      Задача 11.1. Никаких двойных записей

      Два клиента одновременно нажимают «Записаться» на 15:00 к одному мастеру. Проверка «свободно ли» в Java не спасает: обе транзакции видят слот свободным. Сделайте так, чтобы база сама не пустила пересекающиеся записи.

      Показать решение

      Ограничение запрещает две активные записи одного мастера с пересекающимися интервалами (&&). Расширение btree_gist нужно, чтобы в одном GiST-индексе сравнивать и число (=), и интервал. Отменённые записи (status не ACTIVE) не мешают занять время снова. Гонка решена там, где она возникает, — в базе.

      Задача 11.2. Свободные слоты с учётом часового пояса

      Напишите метод, который для дня, часов работы и длительности услуги вернёт свободные слоты мастера в Риге, исключая занятые интервалы.

      Показать решение

      Интервалы [s, e) и [b.start, b.end) пересекаются, если каждый начинается раньше конца другого. Сравнение идёт по Instant (UTC), поэтому переход на летнее время не ломает расчёт: atZone сам сдвигает несуществующее время 03:30 на 04:30. Тест обязательно для 29 марта 2026 года — дня перехода.

      Задача 11.3. Напоминания без дублей

      Приложение работает в двух экземплярах, и в каждом раз в минуту запускается задача «отправить напоминания о записях через 24 часа». Как сделать, чтобы клиент не получил два одинаковых напоминания?

      Показать решение

      FOR UPDATE блокирует выбранные строки до конца транзакции, а SKIP LOCKED заставляет второй экземпляр пропустить их и взять другие. Отметка reminded_at и событие в outbox сохраняются в той же транзакции, поэтому повторного напоминания не будет даже после перезапуска.
