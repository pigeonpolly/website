## Правка блоков на сайте
- Меню аккаунта → «✏️ Править страницу» (`site/assets/site-edit.js`, грузится только по нажатию). Нажатие на блок открывает панель: Текст / Цвета / Код, «Скрыть блок», «Вернуть как было».
- Блоки помечены при сборке атрибутом `data-ppb`: `blk-<имя>` для `{{block:..}}` (общий для всех страниц), `<страница>.<N>` для остальных элементов верхнего уровня (`mark_editable` в build.py). ВНИМАНИЕ: если менять порядок/количество элементов верхнего уровня на странице, номера N сдвинутся и сохранённые правки могут попасть не в тот блок — проверьте Кабинет → «🧩 Правки сайта».
- Правки хранятся в D1 `site_blocks (id, lang, html, hidden, page, updated_at)`; lang = en/ru/lv (HTML блока), `*` + hidden = скрыт на всех языках. API: `GET/POST /api/admin/blocks`.
- Все HTML-страницы идут через worker (`run_worker_first: ["/*", "!/assets/*", "!/images/*", "!/files/*"]`), `sitePage()` подменяет блоки через HTMLRewriter; `?raw=1` — оригинал. ETag = метка файла + версия правок.
- Правка в базе перекрывает код блока из репозитория: если меняешь блок в коде, а у него есть правка в базе, посетители увидят правку. Список — Кабинет → «🧩 Правки сайта».
- Режим правки, устройство страницы: строка `site_blocks` с id `page:<путь без языка>` и lang `*` хранит JSON `{order: [...data-ppb], custom: [custom-xxxx…]}`; worker добавляет `<style id="pp-order">` (main → flex, порядок через `order`) и дописывает новые блоки `<section class="pp-custom" data-ppb="custom-…">` в конец `<main>` (содержимое — правка блока на языке страницы, иначе любая другая). В панели: «↑ Выше / ↓ Ниже», «＋ Новый блок» (текст, картинка, галерея, цитата, кнопка), «🗑 Удалить блок» (только новые), у картинок «⬆ Заменить файлом» (загрузка в R2 через /api/blog/admin/upload), «＋ Добавить ещё картинку рядом», «✕ Убрать».

## Статистика посетителей
- Алине непонятна Cloudflare Web Analytics, поэтому сайт считает сам. `site/assets/site.js` в конце шлёт `POST /api/hit {p, r: document.referrer, u: {source, campaign} из utm_*, w: ширина экрана, t: сенсорный}` (sendBeacon; на localhost не шлёт без `?track=1`).
- `worker/index.js` `hit()`: роботы по user-agent, /admin и /blog-editor, а также заходы админа не пишутся. Таблица D1 `visits(day, ts, vid, entry, path, lang, src, ref, campaign, device, os, browser, country)`; `vid` = sha256(соль `meta.visit_salt` + день + IP + UA)[:16] — меняется каждые сутки, IP не хранится (в копии сайта `visit_salt` исключена). `entry = 1` — заход извне (реферер не наш сайт): `src` по utm_source → по сайту-источнику (`SOURCES`) → по встроенному браузеру приложения (Instagram/Facebook/TikTok часто не передают реферер) → «Напрямую». Устройство/ОС/браузер — `uaInfo()`, страна — `req.cf.country`. Cron удаляет строки старше 400 дней.
- `GET /api/admin/visits?days=1|7|30|90|365` → `visitStats()`: люди (уникальные за сутки), заходы, просмотры, % с телефона, сравнение с прошлым периодом, «сейчас на сайте» (5 минут), график по дням, источники (+ доля телефонов по каждому), сайты-ссылки, utm-кампании, страницы входа, популярные страницы, устройства, ОС, браузеры, страны, язык.
- Кабинет `#visitors` (`admin.js` `visitors()`): период, карточки, столбики по дням (наведение/нажатие — подпись), полоски по разделам, сохранённые ссылки с utm-метками: таблица D1 `utm_links(path, source, campaign, note)`, `POST /api/admin/links` (добавить; `{delete: id}` — удалить), в `visitStats().links` — заходы и люди всего и за период (совпадение по `campaign` + `src = utmSource(source)`); перед сохранением страница проверяется HEAD-запросом (нет такой — ошибка); метки, которых нет в списке, — «Другие метки». Политика конфиденциальности (3 языка) описывает этот подсчёт.

## Защита админки
- **Защита админки** (12.10.2026, кабинет → «🔐 Защита», `/admin/#security`). Раньше админ = любой вход с почтой из `ADMIN_HASHES`. Теперь:
  - **PIN**: meta `admin_pin` = `соль:PBKDF2-SHA256(100 000 — максимум в Workers)`, 4–12 цифр. Если PIN задан, `isAdmin(u)` для пользователя из сессии (у него есть `_tok`, `_pin_ok` из `currentUser`) истинно только при `sessions.pin_ok = 1`; для чужих строк users — только «кто это» (`adminIdentity`). Ввод: POST /api/admin/pin/verify (5 ошибок → замок на час, meta `pin_fail`); на любой странице админу без PIN всплывает окошко «🔐 PIN админа» (account.js `pinAsk`, whoami отдаёт `pin: 1`); кабинет без PIN показывает форму PIN. Смена/удаление — POST /api/admin/pin/set {pin} (другие устройства должны ввести заново).
  - **Код восстановления**: POST /api/admin/recovery/new (только при заданном PIN) — 20 знаков `XXXXX-…`, показывается один раз (скачать .txt / распечатать), хранится только `sha256('rc:'+код)` в meta `recovery_hash`. POST /api/recover {code} — любой вошедший через Google: становится единственным админом (meta `admin_ids`), вход по почте из ADMIN_HASHES отключается (`admin_email_off` = '1'), сессии прежних админов удаляются, PIN сбрасывается, код гаснет (одноразовый), `backup_token` меняется. Ошибки — замок на час для этого пользователя (`rc_fail:<id>`). Не-админ на /admin/ видит «Этот кабинет только для админа» и форму кода.
  - Настройки защиты кэшируются 15 с (`loadSec`). `admin_pin`, `recovery_hash`, `pin_fail`, `rc_fail:*` не попадают в резервные копии.
  - Вернуть вход по почте после восстановления — только правкой meta (`admin_email_off`) / кода.

`/admin/` — `src/pages/admin.html` + `site/assets/admin.js` (стили `.adm-*` в `site/assets/style.css`). Видит только админ (с PIN, см. «🔐 Защита»).

## Как устроено

- **Разделы — один список `ADMIN_SECTIONS`** в начале `admin.js`: `{ id, ic (значок), name, group, about, open?, href?, focus?, count? }`. Меню строится из него, группы — `ADMIN_GROUPS`. Новый раздел = одна строка списка (+ функция экрана в `SECTIONS`, если экран новый).
  - `open` — показать экран другого раздела (например, «Подарки и зарплата» = экран «Все птицы»);
  - `href` — раздел живёт на своей странице (Блог, Нарисуй мне, Ключ Gemini), в меню со стрелкой ↗;
  - `focus` — к чему прокрутить экран (свёрнутое раскроется, место мигнёт);
  - `about` — строка «что здесь делается» над экраном;
  - `count` — красный счётчик в меню (из `/api/admin/inbox`).
- Первый экран — **📥 Входящие** (`/admin/` или `/admin/#inbox`; старый `#overview` ведёт туда же). Только то, что ждёт Алину: комментарии на проверке, заявки «Нарисуй мне», новые подписчики, красные пункты автопилота, пустые окошки адвента (с октября), правки сайта поверх кода, запланированные статьи. Пусто — «Всё спокойно ✓». Ниже свёрнута «📊 Статистика сайта» (прежний «Обзор»).
  - API: `GET /api/admin/inbox` (worker/index.js). «Новые подписчики» — после `meta.inbox_subs_seen`; открыть раздел «Подписчики» = посмотрела (`POST /api/admin/inbox/seen {k:'subs'}`). Так же «Нарисуй мне» (`k:'req'`, нажать ссылку во Входящих или в меню) и «Правки поверх кода» (`k:'edits'`, открыть раздел «Правки страниц»): во Входящих только новые с прошлого просмотра, иначе висели вечно.
- Каждый экран: строка «что здесь делается» → главная кнопка сверху → тонкая настройка свёрнута (`details.adm-fine`) → опасное внизу в красной рамке (`.adm-danger`: Опустошить полки, Восстановить из копии, Вернуть правила по умолчанию, Убрать PIN).
- **Админ-полоска** на каждой странице сайта (в полоске цифр над шапкой, `account.js` → `adminStrip()`): «✏️ Править страницу» (если на странице есть блоки `data-ppb`) и «⚙ В кабинете: …» — магазин → Магазин, галереи и палитры → Картины, статья → редактор этой статьи, челлендж → Челлендж, адвент → Адвент, стая → Стая, игры → Награды игр, профиль птички → Все птицы, остальное → Входящие.
