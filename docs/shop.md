## Магазин
- 🛍 Магазин `/shop/` (src/pages/shop.html, вкладка в «Играх», кнопка на /flock/): весь каталог `PPBirds.GIFTS` с ценой и остатком из таблицы `shop` (GET /api/shop); по умолчанию всё «нет в наличии» (цена 0, количество 0). Покупка POST /api/shop/buy: проверка остатка, пуговок и что вещи ещё нет; вещь сразу в сумке (gifts status 'bag', note 'shop'). Кабинет → «🛍 Магазин» (/api/admin/shop): цена и количество для каждой вещи, фильтры и поиск, сохраняется сразу.
- Продать: «💰 Продать · N 🔘» у любой вещи в сумке (и легендарной) → confirm → POST /api/gift/sell: строка gifts удаляется, в магазине остаток +1 (строки нет — создаётся с ценой из каталога), птичке + `RULES.sellPrice` пуговок (button_log kind 'sell', ref = id подарка), вещь снимается/убирается из комнаты. Цена одна на все вещи; настраивается в кабинете → «📜 Правила» → Магазин: `sellOn` (вкл/выкл) и `sellPrice` (0–10000, по умолчанию 5). Клиенту уходит `me.btn.rules.sell` (= `BTN.sell`, null — продажа выключена, кнопки нет, сервер отвечает 403 'off').
- Кабинет → Магазин: легендарные строки подсвечены жёлтым с ярлыком «★ легендарная». Магазин: сверху блок «🛍 В наличии», ниже «Нет в наличии» (фильтры по видам и темам действуют на оба). Одну вещь можно иметь до 3 штук (`SHOP_MAX`, считаются копии в сумке и неоткрытые), легендарные (`LEGEND` в worker/index.js — тот же список, что в birds.js) — 1 штуку, и дарить их нельзя (ошибка 'legend'). Получателю подарок нельзя, если у него уже 3 таких. В сумке одинаковые вещи показываются одной с «×N».
- «Коллекции» на /flock/ убраны (дублировали магазин). В магазине — весь каталог: в наличии сверху, остальное «Нет в наличии»; отметки «у вас N из 3».
- В каждой категории вещь со значением `'?'` — «🎲 Сюрприз: <категория>» (картинка — подарок с вопросом, room.js `surpriseIcon`; `PPBirds.withSurprise(kind)` = ['?', ...GIFTS[kind]] — в магазине, окне адвента и окне подарка в кабинете, в таблице цен магазина). Сервер (`surprise` в worker/index.js) при покупке, открытии окошка адвента, подарке одной птичке и «Подарить всем» заменяет '?' на случайную вещь этой категории, которой у птички ещё нет (кроме легендарных). Если таких не осталось — магазин отвечает 'all', в адвенте вещь пропускается.
- Список вещей для сервера — site/assets/catalog.json, собирает build.py (`node tools/catalog.js`, выполняет birds.js + room.js). После изменения каталога — просто пересобрать сайт.
- Вкладки магазина (src/pages/shop.html `tabs()`, `.shop-tabs/.shop-tab` в style.css): 🐦 Для птички (по умолчанию) · 🏠 Для комнаты · 🎲 Сюрпризы · 🃏 Карточки. Вкладка = `F.grp` (bird/room/any/cards; запоминается, ссылка `/shop/#room`, `#cards`…); «Карточки» показывает `#cards`, остальные — список вещей (ненужный раздел — класс `.shop-off`). Строки «Для кого» в фильтрах больше нет. Вкладка «Сюрпризы» — «🎲 Сюрприз» каждой категории + категория any, одним списком.
- Фильтры магазина (src/pages/shop.html, `F` = { show, grp, kind, theme }, запоминаются в localStorage `pp-shop-f`): панель из строк «Показать» (🛍 В продаже — по умолчанию / 🎒 Что у меня есть — только вещи из сумки / Всё — в продаже + «Нет в наличии»), «Для кого» (Все / 🐦 Для птички / 🏠 Для комнаты / 🎲 Сюрпризы; группа — по `PPBirds.ROOM_KINDS`), «Что» (виды вещей выбранной группы, только для птички/комнаты), «Тема» — выпадающий список (без темы «Сюрприз», она = группа) и «✕ Сбросить фильтры». Стили `.shop-bar/.shop-row/.shop-lab/.shop-theme` в style.css.

Ниже фильтры «Сколько» (Все / В продаже / ⚠️ Мало 1–3 / ✕ Нет в наличии), «Порядок» (по видам / меньше / больше), «Что» (вид или тема); в списке столбцы «Ценность 🔘» (редактируется), «Остаток», «Цена сейчас». ## Цены и экономика
- Цены магазина. `shop.price` = ценность вещи (цена при обычном запасе: 10 шт., у легендарных 3). Ценность считает tools/catalog.js (`value()`: вид вещи, размер вещи для комнаты, анимация, свечение, легендарность; небольшой разброс по имени; округление до 5) → `catalog.json` `prices`. Ориентир: птичка, рисующая каждый день, получает ~400 🔘 в месяц; еда 15, шапки 30–45, мебель 20–130, обои 70, виды 80–130, анимации 80–100, легендарные 500–650, «🎲 Сюрприз» категории — медиана ×1.2. Один раз сервер ставит всем вещам ценность из каталога (`ensurePrices`, meta `prices_v1`; перезаписывает старые цены). Цена для покупателя — `effPrice(base, stock, leg)` = ценность × (норма/остаток)^0.4, от ×0.75 до ×2.5, округление до 5 (то же в admin.js). /api/shop отдаёт `price` (сейчас) и `base`; в магазине пометки «▲ осталось мало» / «▼ много в наличии». Покупка присылает цену, которую видел человек; если она изменилась — 409 `price` и «Цена только что изменилась».
- Кабинет → Магазин, экономика: над таблицей остатков — пуговок у всех птичек (с ником, не заблокированы; admin/shop → `economy`), в среднем на птичку, средняя цена вещи в продаже и оценка «цена сейчас ÷ ценность» по вещам в продаже (<0.92 — 🟢 дешёвые, >1.15 — 🔴 дорогие, иначе 🟡 нормальные) + «средней птичке хватает на ~N вещей». Кнопки «⚖ Выровнять» (всем вещам ценность из каталога), «⬆ Дороже» / «⬇ Дешевле» на N % (ценность всех вещей с ценой > 0, округление до 5, минимум 5) — POST /api/admin/shop/reprice {mode: reset|up|down, pct}. В таблице категорий колонка «Всё вместе стоит» = Σ (цена сейчас × остаток).
- «Мало / обычно / много» в магазине — от числа птичек (users с ником, не заблокированные): `stockLevels(birds)` в worker/index.js, пересчёт в `loadRules` (раз в 15 с) → `STOCK = {birds, low, norm, many, lowLeg, normLeg, manyLeg}`. Мало = 1…birds×lowPct% (5%), обычный запас = birds×normPct% (20%; при нём цена = ценности, `effPrice`), много = от birds×manyPct% (50%); у легендарных — legendPct% (25%) от этих чисел; всё минимум 1. Кабинет → Магазин: фильтры «⚠️ Мало», «📦 Много», кнопка «↻ Пополнить все закончившиеся, кроме легендарных — по N шт.» (#adm-refill, по умолчанию N = обычный запас, не зависит от фильтров). В магазине у остатка подпись «· мало» / «· много».
- `btnOf(pct, unit)` = max(1, round(pct % × avg)). Правила в %: gameLevelPct (2; × (1 + десяток), каждый номер уровня раз в сутки), gameRecordPct (4; за каждый уровень выше прежнего личного рекорда, один раз навсегда — button_log kind 'gamerec'), gameDayMaxPct (0 — без лимита), gameKingPct (10), potion1Pct (4), potion2Pct (12), potion3Pct (35), potionAgainPct (1), potionDayMaxPct (60; 0 — без лимита). `gamePrices(unit)` — текущие суммы: /api/game (per, record, king, max, avg), /api/potion → rules (p1, p2, p3, again, max, avg), /api/admin/rules → gamePrices (в «📜 Правилах» рядом с % видно «→ сейчас N 🔘» и блок «🎮 Как считаются награды»). Старые ключи gameLevel/gameDayMax/gameKing/potion1…potionDayMax больше не используются.
- **Цены сами, Алина меняет только % категорий и цены легендарных** (11.10.2026; заменяет индексацию выше — она отключена, k = 1, иначе цены и пуговки разгоняли бы друг друга). worker: `priceNow(kind, item, base, stock)` / `baseNow` / `shopRow` (поле `leg`): обычная вещь = ценность из каталога (`CAT_P` = catalog.json prices, грузится в loadRules) × `RULES.catMult[kind]`/100 × `PLEVEL.L` × коэффициент остатка (effPrice); легендарная = ровно shop.price (без округления и множителей). `autoPrice(env)` (cron, раз в сутки; при отсутствии meta — сразу в loadRules) → meta 'price_level' {day, L, income, target, active, avg}: income — медиана заработка за день активности у птичек, зарабатывавших ≥ 3 разных дней из 14 (без 'admin', 'salary', 'sell'); target = income × `RULES.priceDays` (4); если средний кошелёк активных > 10 средних вещей — ×1.15; L двигается к target/средняя ценность не больше ±10 % в сутки, в пределах 0.2…5; первый запуск — L такой, чтобы средняя цена осталась прежней. POST /api/admin/shop/cats {mult: {kind: %}} (10…1000, 100 — обычная). POST /api/admin/shop: у обычных вещей ценность не меняется (только остаток), у легендарных — цена; ответ {base, now}. Кабинет → Магазин: сверху «🏷 Цены категорий» (% + диапазон цен) и «★ Легендарные — цена каждой»; у обычных вещей поле «Ценность» убрано, кнопки «Выровнять / Дороже / Дешевле» убраны. Награды игр — % от постоянной опорной цены (`gameUnit` = meta 'index_base', иначе 50). «🤖 Автопилот» показывает уровень цен и заработок.

## Правила (кабинет → 📜)
- Кабинет → «📜 Правила» (admin.js `rules()`, `#rules`): сверху настройки, снизу «📖 Все правила сайта» — свод обычным текстом с текущими числами. Хранятся в meta `rules` (JSON) поверх `RULE_DEFAULTS` (worker/index.js); `loadRules(env)` в начале каждого API-запроса (кэш 15 с), `cleanRules` проверяет диапазоны (`RULE_NUM`, `COND_RANGE`). GET/POST /api/admin/rules ({rules} или {reset: true}). Что настраивается: пуговки (daily, upload, comment, commentsPerDay, friend, pick → переписываются в `BTN`), награды за уровни (`levels`) и бейджи (`badges`), условия бейджей (`cond`: early/earlyBefore, owl/owlFrom/owlTo, ten, fifty, hundred, inkmaster, comeback, weekend, alt, clock/clockWin, monthly, veteranMonths/veteranPer, collector), магазин (shopMax, legendMax, lowPct/normPct/manyPct/legendPct, priceMin, priceMax — `legMax()`, `effPrice`), адвент (adventLastJan, adventButtons, adventSpecialButtons), ИИ (aiStreak — работы 🤖 в серии, `streakDays()`; aiUpload — пуговки за загрузку 🤖). Клиент получает их: /api/me → `btn.rules` (с `cond`; описания бейджей в sketch-wall.js — с подстановками {n} через `condVals`), /api/shop → `max`, `legendMax`, admin/shop → `pricing` (= STOCK + priceMin/priceMax), /api/shop → `lvl`, /api/advent → `lastJan`. Дни уровней (1, 3, 7…) не меняются. Полученное не отнимается. Статический текст на странице адвента («до 23 января») сам не меняется.

## Зарплата и пополнение
- Зарплата: кабинет → Птицы → «💌 Выдать зарплату» (prompt: сколько 🔘 каждой) → POST /api/admin/salary {amount 1–10000}: всем птичкам с ником (не заблокированным) запись button_log kind 'salary' (ref 'sal…', `seen = 0`) и сразу +N к `users.buttons`. /api/whoami отдаёт `user.salary` — неоткрытые конвертики; account.js `salary()` на любой странице показывает диалог #acct-sal «Тебе письмо!»: конверт качается, «Открыть конвертик» — клапан откидывается, письмо выезжает («Привет, @ник! Администрация Воббленда проводит социальную поддержку птичек и иногда выдаёт им зарплату. Твоя зарплата: +N 🔘», несколько невскрытых — сумма), сразу POST /api/salary/seen (seen = 1). Анимация — только CSS (.sal-*, style.css).
- Ежедневное пополнение магазина: `autoRestock(env, force)` в worker/index.js, вызывается из `scheduled` (cron каждый час в :17) и проходит раз в сутки по Риге (meta `restock_day`; итог — meta `restock_last` {day, at, to, items}). Всем вещам каталога и строкам `shop`, кроме легендарных (`LEGEND`, `any|legend`), только закончившимся (stock 0 или строки ещё нет) остаток = цель, остальные не трогаются; цель = `RULES.restockTo`, а 0 — «обычный запас» `STOCK.norm`. Настройки — «📜 Правила» → Магазин: `restockOn` (по умолчанию вкл), `restockTo` (по умолчанию 0) и кнопка «↻ Пополнить сейчас» (POST /api/admin/shop/autorestock — то же самое принудительно). Локально cron проверяется через `curl localhost:8787/cdn-cgi/handler/scheduled`.
- Этап 4 А: окно зарплаты (#acct-sal) переехало в ленту «конвертика» (news.js, вид `salary`): письмо открывается в карточке, анимация CSS `.nw-salary` / `.sal-*`, затем POST /api/salary/seen.
- **Налог** (8.2 доп., 17.10.2026): кабинет → Птицы → «🧾 Списать налог» (`taxDialog` в admin.js: сколько — N 🔘 или N % от пуговок; у кого — у всех / не заходили ни разу после регистрации и прошло больше месяца (`COALESCE(last_seen, created_at)` < created_at + 1 сутки) / не заходили дольше недели…года; внизу сразу «Птичек заплатит, всего 🔘» по списку птиц) → POST /api/admin/tax {amount, unit 'btn'|'pct', who 'all'|'never'|'idle', days}: птички с ником, не заблокированные, с пуговками > 0; запись button_log kind 'tax' (ref 'tax…', amount < 0, seen = 1), пуговки не ниже 0; ответ {count, total}. Птичке письма нет.
