# Блог

## Кратко
- Блог `/blog/` (+ /ru/, /lv/): статьи на трёх языках, разделы, теги, лайки, комментарии, поиск.
- Страницы блога собирает worker: `worker/blog.js` (подключён из `worker/index.js`), маршруты `/api/blog/*`.
- Редактор `/blog-editor/`: `site/assets/blog-editor.js` (только админ). Главная: `src/blocks/home-blog.html` + `home-blog.js`.
- Перевод — только Gemini (`GEMINI_KEY` или meta `gemini_key`). Картинки — R2 `MEDIA`.
- D1: `blog_posts`, `blog_likes`, `blog_comments`, `blog_tags`, `blog_sections`.

## Устройство
- Сервер: `worker/blog.js` (подключён из `worker/index.js`). Страницы `/blog/`, `/blog/<slug>/` (+ `/ru/`, `/lv/`) собирает worker: берёт готовую `site/<lang>/blog/index.html` и подменяет всё между `<!--BLOG-->` и `<!--/BLOG-->`, title/description/canonical/hreflang/og. Если база недоступна — отдаётся статическая заглушка.
- `wrangler.jsonc`: `run_worker_first` — `/api/*`, `/media/*`, `/sitemap-blog.xml`, `/blog/*`, `/ru/blog/*`, `/lv/blog/*` (без `/api/*` в списке API перестаёт работать!). R2 `MEDIA` = бакет `pigeonpolly-media` (картинки статей, отдаются по `/media/...`), `AI` = Workers AI (перевод `@cf/meta/m2m100-1.2b`, бесплатный дневной лимит; при лимите ошибка `ai_limit` → «попробуйте завтра»).
- Таблицы D1: `blog_posts` (поля по языкам `t_/d_/b_/tags_` + `ru/en/lv`, `featured` = ★ для главной), `blog_likes` (по cookie `pp_a`), `blog_comments` (аноним = «птица + 2 цифры» из `pp_a`, вошедший — ник челленджа со ссылкой `/challenge/#@ник`; IP только хешем с солью `meta.blog_salt`; со ссылками → `pending`; `meta.blog_strict=1` → 1 комментарий в час с адреса, иначе 3 за 10 минут).
- Локальная проверка: wrangler dev с отдельным конфигом (D1/KV/R2 локальные, `DEV_FAKE_LOGIN=1`, без AI — перевод подменяется на «[ru] текст»).

## Редактор и перевод
- Редактор: `/blog-editor/` (`site/assets/blog-editor.js`, только админ, в sitemap нет, закрыт в robots.txt). Вкладки RU/EN/LV, «Перевести» — с открытой вкладки на две другие. Вставка из Google Docs чистится (жирный/курсив из span, картинка+подпись → figure/figcaption, заголовок «Название» → поле заголовка); картинки googleusercontent копируются в R2 сразу при вставке (`/api/blog/admin/fetch-image`, при неудаче — через браузер; несдавшиеся обводятся красным) и ещё раз при сохранении. HTML статьи ещё раз чистится на сервере (HTMLRewriter, белый список тегов).
- Перевод: Gemini (секрет `GEMINI_KEY` в Cloudflare; модели по очереди gemini-3.1-flash-lite → gemini-flash-lite-latest → gemini-3.5-flash-lite → gemini-3.5-flash, при занятости — повтор через 8 с, строгий промпт «переводить точно, ничего не добавлять»), абзацы с потерянными тегами и весь перевод при недоступности Gemini — запасной m2m100. Клиент шлёт по 15 фрагментов.
- `src_lang` — язык оригинала (ставит кнопка «Перевести», можно выбрать в редакторе); на других языках внизу статьи тихая пометка `.bp-tr-note` «перевод онлайн-инструментами» со ссылкой на оригинал.
- Сохранение лёгкое: картинки из Google Docs при сохранении больше не перекачиваются (копируются при вставке; если остались ссылки на Google — кнопка «Скопировать их на сайт»). Текст не обрезается (лимит ~900 000 символов → ошибка too_big). Локальной «запасной копии» в браузере больше нет; при ошибке сохранения — alert. После успешного сохранения — сразу список статей (вкладка по статусу) с зелёной строкой `.be-flash`. Статья открывается на вкладке языка оригинала (`src_lang`, иначе первая с текстом).
- Статья и редактор: стрелочки наверх/вниз (`site/assets/scroll-nav.js`); у статьи кнопка «Поделиться» (на телефоне — `navigator.share`, на компьютере — меню: копировать ссылку, Facebook, Telegram, WhatsApp, Pinterest, LinkedIn, X, почта).
- Редактор: теги — «чипы» (Enter/запятая добавляет, Backspace убирает, подсказки из уже существующих), адрес заполняется сам из заголовка (EN, иначе RU транслитом), пока его не правили руками и статья не опубликована; перевод идёт кусками по 6 фрагментов с полоской прогресса на каждый язык. Список: вкладки «Опубликованные / Черновики / Теги» (тег можно переименовать или удалить во всех статьях — `/api/blog/admin/tag`).
- Картинка в редакторе вставляется сразу с `figcaption` (курсор в подписи, Enter → абзац под картинкой); при сохранении пустые подписи убираются, а текст подписи становится alt. Подписи — наклонный `--sans`.
- В панели над текстом — «🖼 Картинки из оригинала» (`mergeImages`): ставит картинки из вкладки-оригинала после того же по счёту абзаца. Подсказка в редакторе: перевод через Google Docs «Инструменты → Перевести документ». Теги по-прежнему переводятся словарём/автоматом.
- Редактор светлый (`.be-app` — белая «бумага», поля и таблицы светлые; панель инструментов фиолетовая).
- Кнопка «🌐 Перевести с RU на EN и LV» вернулась, но статьи переводит только Gemini (`strict: true` → без ключа ошибка `no_key`, при сбое `ai`/`ai_limit`/`bad_key`, слабый m2m для статей не используется; теги — по-прежнему словарь, затем Gemini или m2m).
- Ключ Gemini: `env.GEMINI_KEY` (Cloudflare) или вставляется в редакторе «⚙ Перевод (Gemini)» → `meta.gemini_key` (`/api/blog/admin/gemini-key`, `?test=1` — пробный перевод). Ключ наружу не отдаётся.
- «🖼 Картинки из оригинала» и подсказка про Google Docs остались.
- Редактор статьи: над каждой вкладкой языка — цветная плашка «🇷🇺 Русская версия / 🇬🇧 English version / 🇱🇻 Latviešu versija» и «Перенести в: EN · LV» (`moveLang`: заголовок, описание и текст переезжают; если там уже есть текст — вкладки меняются местами, язык оригинала тоже). Если язык текста не совпадает с вкладкой (кириллица / латышские буквы / латиница), появляется жёлтая подсказка с кнопкой переноса (`guessLang`, `checkLang`).
- Дата статьи меняется в редакторе (поле «Дата статьи», `#be-date` → `published_at` в секундах; если день не менялся — время прежнее). Сервер принимает `published_at` при сохранении (не дальше года вперёд).
- Редактор статьи (с 9.10.2026, по образцу Patreon): заголовок и описание без подписей (крупно, как на странице); панель форматирования всплывает над выделенным текстом (`.be-bubble`); на пустой строке слева кнопка ＋ (`.be-plus` → `.be-plusmenu`: картинка, видео YouTube, цитата, разделитель, H2, «Картинки из оригинала»); все настройки (обложка, язык оригинала, дата и время, раздел, теги, избранное, адрес) — в выезжающей справа панели «⚙ Настройки» (`#be-drawer`); внизу липкая панель: кнопки, автосохранение и «N слов · ~M мин чтения». Автосохранение: черновик/новая статья сохраняются на сервер через 4 с после правки (адрес меняется на #id), у опубликованной — только пометка «есть несохранённые изменения».
- Видео YouTube в статьях: `<figure><iframe src="https://www.youtube-nocookie.com/embed/ID">` — сервер (cleanHtml) пропускает только такие iframe.
- Отложенная публикация: дата и время в будущем + «⏰ Запланировать на …» — статья опубликована, но на сайте (список, страница, поиск, главная, sitemap, лайки/комментарии) появляется только когда наступит `published_at`; админ видит её с пометкой «⏰ Запланирована».
- Блог, защита от дублей (октябрь 2026, у Алины статьи сохранялись по 3–4 копии и падали в черновики): у новой статьи в редакторе метка `post.key` → `client_key` в blog_posts; сохранение без id, но с известной меткой обновляет ту же статью. Кнопка «Сохранить/Опубликовать» ждёт идущее автосохранение; после сохранения автосохранение выключено (`left`). Автосохранение шлёт `auto: true`, и сервер никогда не переводит опубликованную статью в черновик. Уже созданные дубли Алина удаляет сама (галочки → удалить).
- Блог-редактор: «🧹 Убрать дубли» — плашка над вкладками, если есть статьи с одинаковыми заголовками (RU+EN+LV); GET admin/dupes (группы; оставляем опубликованную → с просмотрами/лайками/комментариями → самую полную → самую свежую), POST admin/dedupe {keep, remove} (только настоящие копии; разделы, звёздочка, просмотры, лайки и комментарии копий переходят к оставшейся). Фильтр «★ Избранные» (featured). При поиске — «Ещё N в черновиках/опубликованных · показать». Свой календарь вместо встроенного (неделя с понедельника, дата 09.10.2026): все input[type=date] в редакторе превращаются в скрытые поля + кнопку (значение и события change те же).
- Сноски в блоге: в базе это `[[пояснение или источник]]` в тексте статьи. В редакторе (blog-editor.js) `[[…]]` не видно: при загрузке `fnToChips` превращает их в циферки-«фишки» `<sup class="be-fn" data-fn="…">` (номер — CSS-счётчик), при сохранении `chipsToFn` (в `collect`) — обратно в `[[…]]`, пустые выбрасывает; при переводе (`splitForTranslation`) сноски вынимаются из текста: на их месте метка `<span class="notranslate" data-fnp>` (переводчик её не трогает), сами сноски переводятся отдельными кусочками, а в `rebuild` ставятся обратно как `[[перевод]]` (потерянные метки — в конец последнего абзаца; пробел перед запятой после сноски убирается). Раньше Google ломал `]]` вместе с цифрами («1874» → «18 ]7]4»). На сайте пробел перед циферкой убирается (`footnotes`). Под текстом — список «Источники и примечания» (`.be-fns`, `syncFns` по MutationObserver): у каждой сноски поле, правится сразу, ✕ удаляет; нажатие на циферку в тексте ведёт к её полю, на номер в списке — к месту в тексте. Кнопки «¹» (панель выделения) и «¹ Сноска» (меню «+») ставят циферку в место курсора и сразу открывают её поле. Обычная ссылка в тексте: нажали — окошко `.be-linkpop` (поправить адрес, ↗ открыть, «Убрать»). worker/blog.js `footnotes()` на странице поста превращает их в циферки `<sup class="fn-ref">` (с подсказкой при наведении) и добавляет внизу свёрнутый `<details class="bp-fns">` «Источники и примечания (N)»; голые https-адреса в сносках становятся ссылками. Нажатие на циферку раскрывает список и подсвечивает пункт (site/assets/blog.js), ↩ — назад к тексту. В выдержках и описаниях (`stripTags`) сноски вырезаются.
- Редактор блога, цитаты: `unquote(body)` вынимает выделенные абзацы из цитаты (цитата делится на «до» и «после»; абзац считается выделенным, только если в нём выделен текст — тройной клик задевает начало следующего). Вызывается кнопками «¶» (обычный текст), H2/H3, «⌫» (убрать форматирование); «❝» на цитате — снимает её (переключатель). Раньше `formatBlock p` внутри цитаты ничего не менял.

## Список, главная, теги
- Главная: крупно всегда самая новая статья, справа три последние со ★ (кроме той, что крупно). Поле `pinned` и `/api/blog/admin/pin` остались в базе/сервере, но в редакторе кнопки 📌 нет (по просьбе Алины).
- Теги: в статье только английские (`tags_en`, одно поле в редакторе); перевод — словарь `blog_tags (en, ru, lv)`, новые теги переводятся сами при сохранении статьи, правятся во вкладке «Теги» (`/api/blog/admin/tags`, `tag-set`, `tags-translate`); ссылка `?tag=` всегда по английскому тегу; `tags_ru/tags_lv` в статьях — копия перевода (`syncTagColumns`). Старые теги перенесены в словарь один раз (`meta.blog_tags_v1`).
- Карточки статей и боковая колонка блога — белые.
- Читателю: текст статьи на белой «бумаге», шрифт статей — Lora (`--article`, есть латышские буквы и кириллица; Karla кириллицы не знает); боковая колонка — ★ Избранное (+ `?fav=1`), теги (`?tag=`), архив по годам и месяцам (`?month=YYYY-MM`), популярное. Отфильтрованные списки — noindex.
- Главная: блок `src/blocks/home-blog.html` + `site/assets/home-blog.js` (`/api/blog/home`): новая статья крупно, справа ★-избранные; без статей блок скрыт.
  - ⚠ Позже (8.10.2026): блок блога на главной показывается всегда, без статей — заглушка (см. ниже).
- Блок блога на главной показывается всегда: без статей — заглушка «Первые статьи уже в пути».
- Разделы (`blog_sections`: slug, en/ru/lv, sort; у статьи поле `section`): кнопки над списком `/blog/?section=…`, метка над заголовком статьи и в карточке; управление — вкладка «Разделы» редактора, новый раздел и из выпадающего списка в статье.
- Список: по 8 статей (`?page=N`), поиск `?q=` (заголовки, описания, текст на всех языках и теги), фильтры раздел/тег/месяц/избранное сочетаются; отфильтрованное — noindex.
- Правая колонка: заголовки мелкими заглавными с линиями; избранное и популярное — по 5, без цифр и сердечек; теги по частоте: 1-й золотой, 2–4 фиолетовые, остальные белые, с числом статей.
- Теги: встроенный словарь частых художественных тегов `GLOSSARY` (RU/LV написаны вручную, LV стоит проверить); у тега `checked`, `src` (glossary/auto/manual), `created_at`; вкладка «Теги» сортируется: непроверенные / по частоте / новые / по алфавиту.
- Правая колонка: теги при наведении не белеют (общее `a:hover`), избранное/популярное — в одну строку с «…» и title.
- Блог (список): под заголовком «В блоге N статей» (`t.count`); боковая панель обёрнута в `<details class="bl-sidewrap">` — на компьютере всегда открыта справа, на телефоне (≤960px) стоит над статьями и свёрнута в кнопку «☰ Разделы, теги и архив» (blog.js закрывает её).
- Разделы блога (с октября 2026): traditional-art, technologies, education, pollys-life, tips-guides, stories (с 10.10.2026 называется «Site news / Новости сайта / Vietnes jaunumi», адрес прежний ?section=stories; переименование — разовая миграция meta `sections_news`; добавляется отдельным idempotent INSERT после sections_v2) (одноразовая миграция `sections_v2` в worker/blog.js сняла старые разделы со всех статей). У статьи может быть НЕСКОЛЬКО разделов: колонка `blog_posts.section` — слаги через запятую (`secsOf()`); редактор — галочки в «⚙ Настройках» и в строке списка; массовые действия «добавить в раздел / убрать / только в одном».
- Дата статьи меняется прямо в строке списка (bulk action `date`).

Сервер — `worker/blog.js`, редактор — `/blog-editor/` (`site/assets/blog-editor.js`, только админ).

## Редактор

- Вкладки RU / EN / LV, «🌐 Перевести» и «✨ Gemini», картинки из Google Docs копируются в R2 при вставке.
- «⚙ Настройки публикации» (выезжающая панель): обложка, язык оригинала, **дата и время публикации** (`#be-date` + `#be-time` → `published_at` в секундах, местное время браузера), разделы, теги, ★, адрес.
- Кнопки внизу:
  - черновик: «Сохранить черновик» · **«Опубликовать сейчас»** (всегда) · «⏰ Запланировать на дд.мм чч:мм» (только если будущее время выбрали руками);
  - опубликованная: «Снять с публикации» · «Сохранить изменения»;
  - запланированная: пометка «⏰ Запланирована на …» · «Снять с публикации» · «💾 Сохранить (выйдет по плану)» · «Опубликовать сейчас».
- Автосохранение черновика каждые 4 с после правки. Дату оно отправляет, **только если её трогали руками** в этот раз (`dateTouched`).
- Список статей: вкладки «Опубликованные · ⏰ Запланированные · Черновики · Разделы · Теги». Вкладка «Запланированные» видна, только когда такие есть; в строке — «⏰ Запланирована на дд.мм чч:мм».

## Отложенная публикация

- Запланированная статья = `status = 'published'` и `published_at` в будущем. На сайте (список, страница, поиск, главная, sitemap, лайки, комментарии) её нет до этого момента; админ видит её с пометкой «⏰ Запланирована».
- Над списком, если такие есть: «N статей ждут публикации · Опубликовать сейчас» → `POST /api/blog/admin/bulk {action: 'now'}` (ставит `published_at = сейчас` только запланированным).
- `POST /api/blog/admin/save`: `now: true` («Опубликовать сейчас») → `published_at` = сейчас (или прошедшая дата, выбранная руками). Ответ содержит `published_at`.
- Массовое «Опубликовать сейчас» для черновиков (`action: 'publish'`) — тоже сейчас; сохраняется только дата «задним числом» (раньше создания статьи).

### Ошибка, которую чинили (этап 1)

Черновик публиковался только кнопкой «⏰ Запланировать», а потом лежал в «Опубликованных» без пометки. Воспроизведено в `wrangler dev` (часовой пояс Europe/Riga, 09:15):
1. Выбрали в календаре день без времени → `dateToTs` молча брал **12:00** местного времени → утром это будущее → кнопка становилась «⏰ Запланировать на 16 окт., 12:00».
2. Автосохранение тут же записывало этот `published_at` в черновик, поэтому и при следующем открытии кнопка была «Запланировать».
3. Опубликованная так статья попадала в «Опубликованные» (там были все `status = 'published'`), хотя на сайте её не было.
